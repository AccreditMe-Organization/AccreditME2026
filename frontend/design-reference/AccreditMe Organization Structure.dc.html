Organization Structure, the chart, and the Org unit record

Three surfaces show hierarchy, and each answers a different question. The Tree is where you find and act on any unit. The Chart is where you read the structure and the people in it, and it's the one that gets printed. The record is one unit and everything linked to it: its parent above, its direct children below, and nothing deeper. None of the three repeats another.

§3.3 · Behaviours the chart needs. The build tests p-organizationChart against each one, in this order.
{{ b.id }} {{ b.need }} {{ b.why }} {{ b.gate }}
If PrimeNG fails a required behaviour, the fallback is our own component, not a new library. The chart is a nested flex tree with logical-property connectors, exactly what's drawn above. Keyboard traversal and zoom are small, and a charting library would spend a large part of the 187 kB on layout we don't need. The build should report which behaviour it fails on, and that decides it.
