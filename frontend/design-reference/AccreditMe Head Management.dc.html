Unit head management

The surface is organised around what the unit's headship is, not around the seven backend endpoints. A Headship panel on the org unit record shows the current state and offers only the actions that state allows, each named in the user's words. Two dialogs and four confirms sit behind it. The word “handover” appears nowhere.

The worst case was 6px over — here's the fix
Arabic makes every block 5px taller (84 vs 79 at standard, 76 vs 71 at compact), and the strip is 4px taller (56 vs 52). If the position select kept a message slot, the worst case would be 426. The fix is the §13 rule, applied correctly. The position select is required, it's a closed list, and it defaults to the incumbent's position. So it can never produce a message, and it declares message: 'none'. Without the slot the dialog is 404 in Arabic and 383 in English. It's the same rule, in the same place, in both languages. We didn't raise the cap. We didn't shorten helper text, because text doesn't set a slot's height. We didn't hide the note: it's the audit record the brief asked us to keep. And we didn't let the body scroll, because a scrolling body would put the select and the calendar inside a scroll container, which is exactly the fault artboard 7 exists to prevent. 16px of headroom remains in Arabic, so a two-line strip would still fit. That's why the strip's meta line is clamped to one line with an ellipsis, with the full text on the record it links to.

“From” (من) comes at the inline start — on the right in Arabic — because the order is set by dir, never by left or right. Each date inside is isolated as LTR, so “25 Sep 2026” stays whole instead of reversing. There's no arrow between the two fields: an arrow would have to mirror, and a label can't point the wrong way. Keyboard: arrow keys move day by day in visual direction (→ is earlier in RTL). Tab moves From → Until in reading order.
Why the reason is not a field
For an acting appointment, the reason follows from the unit's state. A unit with a head can only need cover because the head is away: ABSENCE, covering for that head. A vacant unit can only need cover because the post is empty: VACANCY, covering for nobody. If the user picked the reason, they could make the record say something false — “Post is vacant” on a unit with a head. So the dialog sends reason and coveringForUserId without showing them as controls, and states them in the strip at the top. Confirmed by the backend: the reason is forced by whether a head is in post. When a head leaves, Vacate records it, and any cover still running becomes a VACANCY cover.
Warning about the 90-day rule when the choice is made
The Until field has a group message line below it, and that line always describes what the cover will do. With a date: “26 days · the cover ends on its own on 20 Oct 2026”. Without a date: the actual date the condition will fire — “No end date. If this cover is still running on 24 Dec 2026, Setup health will mark Pharmacy At risk” — plus what to do about it, which depends on the reason, the same way the condition's own Fix does. The button changes too: “Cover until 20 Oct” versus “Cover with no end date”. That way the open end is visible in the thing the user clicks. Once saved, the panel shows the cover as a bar that turns dashed after the last known date, with a marker on the day it will be flagged.

Horizon 1 — the same frame, fewer rows
Today the backend knows the current head, a scheduled successor and an active cover. It doesn't keep past periods. So in Horizon 1 the panel shows only the Current view, with those rows, and there's no History switch. We don't show a switch that leads to an empty list, and we don't add a “coming soon” note. ACC-131 adds the switch and the past rows, in the frame the Current view already uses. We shouldn't piece together a Horizon 1 history from the audit log: isHeadVacant is wrong on 32 of 34 units, and a reconstructed history would repeat those errors to a surveyor.
Where the note ends up
The note is part of the audit trail, so we collect it only where the backend stores it. In Horizon 1 that's the successor path, declareHandover. It appears on that history row and in the unit's audit trail, word for word, with the name of the person who recorded it. In Horizon 2, every dated assignment row should accept a note. Proposed for ACC-131, not drawn in Horizon 1: a note on appointments to a vacant unit and on covers. We'll add those fields once the backend stores them, and not before.
